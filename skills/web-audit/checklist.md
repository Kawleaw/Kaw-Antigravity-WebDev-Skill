# Website Audit — Detailed Checklist Reference

Detailed reference checklist for comprehensive website audits. Use this companion file during audits to systematically verify each page crawled.

---

## 1. Content & Copy Quality Checklist

| # | Check Item | What to Look For |
|---|---|---|
| 1.1 | **Lorem Ipsum / Dummy Text** | Any instance of "Lorem ipsum", "dolor sit amet", sample Latin, or unfinished text. |
| 1.2 | **Placeholder Data & Numbers** | Zeroed metrics (0+ customers, 0% uptime, +0), "Name Here", "Job Title", "Company Logo", "Insert image". |
| 1.3 | **Spelling & Typos** | Misspelled words, transposed letters, wrong accents, keyboard slips. (See Thai & English tables below). |
| 1.4 | **Grammar & Syntax** | Broken sentence structures, missing prepositions, subject-verb disagreement, broken punctuation. |
| 1.5 | **Tone & Voice Consistency** | Does every page feel written by the same brand? Does technical/formal tone clash with casual sales copy? |
| 1.6 | **Repetition & Redundancy** | Reusing the exact same buzzphrase or paragraph across multiple sections inadvertently. |
| 1.7 | **Vague / Weak Copy** | Generic buzzwords ("Next-gen solution", "Revolutionizing industry") that fail to explain what the product actually does. |
| 1.8 | **Incomplete Sections** | Headings without accompanying body text, orphan subheadings, broken lists. |
| 1.9 | **Terminology Consistency** | Inconsistent product/feature names (e.g., calling it "Pro Plan" on one page and "Premium Tier" on another). |
| 1.10 | **Conflicting Information** | Numbers or claims that contradict across pages (e.g., "over 5,000 customers" on Home vs "over 10,000" on About). |

### 2.2 Thai Copywriting & Tone Checks
1. **สำนวนแปลแข็งทื่อ (Translationese / Google Translate Feel):**
   - ตัวอย่าง: *"มันถูกสร้างขึ้นมาเพื่อให้คุณสามารถ..."* ➔ ปรับให้เป็นธรรมชาติ: *"ออกแบบมาเพื่อช่วยให้คุณ..."*
   - ตัวอย่าง: *"ทำการคลิกที่นี่เพื่อ..."* ➔ ปรับให้กระชับ: *"คลิกที่นี่เพื่อ..."* หรือ *"เริ่มใช้งานทันที"*
2. **การเว้นวรรคและการตัดบรรทัด:**
   - ภาษาไทยไม่ใช้ space คั่นทุกคำ แต่เว้นวรรคระหว่างประโยคหรือวลี
   - ตรวจสอบคำที่ถูกตัดบรรทัดกลางคำอย่างน่าเกลียดบนมือถือ (เช่น "บริ-การ", "ระ-บบ")
3. **ระดับภาษาและความสุภาพ (Tone Consistency):**
   - ใช้คำสรรพนามสม่ำเสมอทั้งเว็บ เช่น คุณ / พวกเรา หรือ บริษัทฯ ไม่สลับไปมาระหว่างภาษาทางการกับภาษากันเองโดยไม่มีเหตุผล

## 3. English Dialect Consistency (US vs UK)

Ensure the site uses a consistent English dialect rather than mixing conventions haphazardly:

| US English (American) | UK English (British / Commonwealth) | Common Context |
|---|---|---|
| **color** | **colour** | Design, UI settings |
| **organize / organization** | **organise / organisation** | Business, feature descriptions |
| **analyze / analysis** | **analyse / analysis** | Analytics, metrics |
| **center / centered** | **centre / centred** | Locations, alignments |
| **customize / customer** | **customise** | Settings, personalization |
| **license** (noun & verb) | **licence** (noun) / **license** (verb) | Software terms, pricing |
| **gray** | **grey** | Palette, theme tokens |
| **catalog** | **catalogue** | Product listings |
| **program** | **programme** | Schedules, initiatives |
| **check** (bill/review) | **cheque** (payment) / **tick** (box) | Forms, checkouts |
| **fulfill** | **fulfil** | Orders, deliveries |

## 4. UX Structure & Information Architecture Checklist

| # | Check Item | What to Look For |
|---|---|---|
| 4.1 | **5-Second Hero Clarity** | Can a visitor determine product purpose, target audience, and primary action within 5 seconds? |
| 4.2 | **Clear Value Proposition** | Headline answers: "What problem does this solve?" rather than vague vision statements. |
| 4.3 | **Self-Selection Paths** | Distinct paths or tabs for different user personas (e.g. For Creators vs For Brands, Starter vs Enterprise). |
| 4.4 | **Persuasion Sequence** | Flow follows: Problem ➔ Solution ➔ How It Works ➔ Proof / Results ➔ Offer / Pricing ➔ FAQ ➔ Final CTA. |
| 4.5 | **Cognitive Overload** | No section contains more than 3-4 competing ideas, banners, or primary buttons simultaneously. |
| 4.6 | **Missing "How It Works"** | Complex or unfamiliar software must have a 3-step simple walkthrough of how it functions. |
| 4.7 | **Missing FAQ** | High-ticket or commitment products must address cancellation, security, refund, and onboarding FAQs. |
| 4.8 | **Sticky / Back-to-Top Navigation** | On long scrolling sales pages, user should never feel stranded without navigation or CTA. |
| 4.9 | **Mobile Text Pacing** | Paragraphs should not exceed 3-4 lines on mobile viewports to prevent walls of text. |
| 4.10 | **Dead Ends** | Every page must end with a recommended next step or final CTA before the footer. |

## 5. Conversion & Persuasion Checklist

| # | Check Item | What to Look For |
|---|---|---|
| 5.1 | **CTA Specificity** | Labels describe the benefit: "Get Instant Access", "Book 15-Min Demo" rather than generic "Submit" or "Click Here". |
| 5.2 | **CTA Hierarchy** | One clear Primary CTA per screen; secondary actions (e.g. "Watch Video", "Read Docs") use subtle styling. |
| 5.3 | **Social Proof Credibility** | Testimonials contain real names, titles, photos, or company logos. Round, vague stats ("100% happy clients") flag as unconvincing. |
| 5.4 | **Social Proof Placement** | Reviews placed *after* the value claim and *adjacent to* pricing or signup fields. |
| 5.5 | **Pricing Transparency** | Clearly states billing frequency (monthly vs annual), currency, hidden fees, or setup costs. |
| 5.6 | **Price Anchoring** | Highlights a "Most Popular" or recommended tier; calculates daily cost or savings on annual plans. |
| 5.7 | **Risk Reversal & Guarantees** | Explicit statement of refund policy, "No credit card required", or "Cancel anytime" near the final action. |
| 5.8 | **Urgency / Scarcity Validity** | If countdown timers or limited slots are used, ensure they are authentic and not artificially resetting on refresh. |
| 5.9 | **Soft Conversion / Secondary Offer** | For visitors not ready to buy: newsletter signup, free guide, template, or calculator to capture interest. |

## 6. Technical QA & SEO Checklist

| # | Check Item | What to Look For |
|---|---|---|
| 6.1 | **Broken Links (404s)** | Any navigation link, footer link, or CTA button leading to an error page or non-existent anchor `#`. |
| 6.2 | **Orphan Pages / Unlinked Nav** | Menu items with `href="#"` or empty links. |
| 6.3 | **Unique Page Titles** | Each page has a distinct, descriptive `<title>` (e.g., `Pricing | Acme — Cloud Analytics`). |
| 6.4 | **Meta Descriptions** | Present, relevant, and between 120-160 characters for key crawled pages. |
| 6.5 | **Open Graph (Social Sharing)** | `og:title`, `og:description`, and `og:image` configured for preview cards on Slack, Twitter/X, and Facebook. |
| 6.6 | **Image Alt Attributes** | Meaningful alt text for diagrams and hero graphics; purely decorative images tagged with `alt=""`. |
| 6.7 | **Form Field Validation** | Obvious indicators for required fields, clear error messages when invalid email is entered. |
| 6.8 | **Duplicate Content Variants** | Duplicate sections rendered due to improper responsive breakpoint hiding (common in no-code builders). |

## 7. Creative & Brand Pacing Checklist

| # | Check Item | What to Look For |
|---|---|---|
| 7.1 | **Visual Hierarchy** | Clear scale ratio between H1, H2, H3, and body text. |
| 7.2 | **Visual Rhythm** | Variety in layout structure (e.g. split hero ➔ 3-column benefits ➔ full-width quote ➔ bento grid). |
| 7.3 | **Photography & Asset Cohesion** | Consistent imagery style (not mixing 3D cartoons, corporate stock photography, and hand-drawn doodles without clear intent). |
| 7.4 | **Team & About Authenticity** | Real portraits, real bios, verified LinkedIn/social links rather than generic stock avatars. |
